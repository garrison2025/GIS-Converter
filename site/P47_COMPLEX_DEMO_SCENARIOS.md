# P47 — Real line, GPS track and polygon-hole demo scenes

## Problem solved

P46 offered a real one-click example file for all 19 conversion routes, but
each example was the **same simple point**. A person trying a route could
not preview whether polylines, GPS tracks or polygon inner rings would
survive conversion. P47 adds **source/target-specific synthetic GIS data**
without misleading visitors into trying geometry families the output
cannot represent.

## Implemented features

On every existing converter page, an **Example geometry** selector appears
beside **Try a sample [source] file**. The initial selection remains
**One WGS84 point**, preserving the P46 path. Supported additional choices:

- **Three-vertex line / GPS track**: synthetic path with three
  explicitly known WGS84 locations and an interior vertex. The GPX source
  is a valid three-waypoint-in-a-track GPX track with explicit sample
  timestamps and elevations; elevations/timestamps are not promised for
  every output format.
- **Polygon with one interior hole**: one closed five-position exterior
  ring and one closed five-position inner ring; no unknown source data,
  no external image, maps or API calls.

The UI lists options using the exact source/destination format pair:

| Source or output constraint | Scenarios presented |
| --- | --- |
| CSV source or target | **Point only**; there is no CSV polygon/line claim |
| GPX source | Point or GPS track; **no polygon** |
| GPX target | Point or line; **no polygon** |
| KML, KMZ, GeoJSON, Shapefile with compatible output | Point, line, polygon with hole |
| Unsupported route | No invented converter link or scenario |

Changing the scenario dropdown itself does **not** read local files,
replace the current file, upload anything or start conversion. The example
is materialized only after clicking Try a sample, with the existing
file-selector action and another explicit **Convert** click required.

Files are less than 16 KiB each; ZIP output assembly is loaded only on
direct request. Normal P42 low-memory constraints, P44 error recovery,
P45 repeat conversion / Blob revocation and all 19 browser GDAL routes
remain intact.

## Binary interoperability

The demo code writes a full synthetic ESRI Shapefile **PolyLine (type 3)**
or **Polygon (type 5)**, one correctly indexed record, data ranges,
`.shx/.dbf/.prj/.cpg` sidecars and matching WGS84 coordinates. The
Polygon exterior is **clockwise** and the interior hole
**counter-clockwise**, as required by the native Shapefile format. This
source is **not generated by the website's own GDAL converter**.

The separate native CLI regression invokes installed `ogr2ogr` and
`ogrinfo` on these generated source files. It must verify the 3 line
vertices, 2 polygon rings, inner-hole area, field attributes and WGS84
before an automated interoperability claim is made.

## Tests and restrictions

- `npm run smoke:scenario-unit`: per-route eligibility, unsupported
  geometry exclusions, GeoJSON/KML/GPX/KMZ validity, actual SHP record
  offsets, winding and binary sidecars.
- `npm run smoke:scenario-native`: **real independent native GDAL**
  reading the generated PolyLine and polygon-with-hole Shapefiles, not
  self-validation with browser GDAL.
- `npm run smoke:scenario-browser`: real browser GDAL/WASM Worker for
  each supported non-point scenario, checking downloaded geometry parts
  or XML/GeoJSON structure and independent quality JSON; plus mobile
  viewport WebKit polygon-hole ZIP conversion.
- After merging, an exact Cloudflare Pages main-SHA workflow rechecks
  the same scenarios, all original 19 upload/download routes and all
  19 standard converted preview/report cases.

**Important limit:** these are synthetic WGS84 geometries, not full GIS
topology certification or proof that every property, layer style,
attachment, elevation or time survives arbitrary conversions.
The original safety guards may still block detected data loss, and the
person is instructed to review results with independent GIS software.

**Public state:** engineering preview, Cloudflare Pages `noindex` and
`robots.txt Disallow: /`. No SEO launch, user account, server upload,
payment activation or new recurring service cost is introduced.
Manual QGIS GUI and physical low-RAM phone validation remain separate.
